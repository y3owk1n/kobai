# The reference Project is the release gate, and the content Plugin is built first

ADR-0024 removed the compensating test that ADR-0007 and ADR-0013 relied on — a real store
exercising the extension surface as a side effect of shipping. This replaces it deliberately.

A **reference Project** lives in the repository, generated by `create-kobai`, wired with
real Step overrides and at least one Plugin. It is **upgraded across every Core major in CI
using the shipped codemods**, and "the reference Project upgrades cleanly" is a release gate.
That makes ADR-0001's central promise a thing that is continuously tested rather than a
thing that is asserted.

## Build the hardest Plugin first

ADR-0023 makes the content platform the most demanding possible proof that the extension
surface is real. **It is therefore built early, not last.** Built last, the surface is
discovered to be wrong last — after Core, the Admin, and every other Plugin have been built
on the assumption that it was right. Built first, the discovery is cheap and the correction
lands before anything depends on it.

## Consequences

ADR-0013's standing rule — *if the case cannot be built without changing Core, the extension
surface is wrong; fix the surface, do not add the feature* — is unchanged, but its test case
is now the reference Project and the content Plugin rather than the printing store.
